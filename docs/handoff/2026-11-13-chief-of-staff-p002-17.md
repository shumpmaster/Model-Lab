## Mechanics learned this session
- Keep work local while an answers-only pull request is open, so it stays answers-only; push after it merges (the branch then fast-forwards).
- Record an answer from a separate worktree (`git worktree add <dir> -B <push branch> origin/main`), so helpers reading the shared checkout are not disturbed. Switching the shared checkout while a helper reads it is a slip.
- An ordinary push suffices after the push branch's pull request merged: the remote tip is in main, so a branch from main fast-forwards it. A force push is refused here.
- The pr-body check's opening paragraph takes 15 to 150 words; a records-only Context bullet is exactly `- none beyond the ruling quoted in Why`. Test with `governance_checks.py pr-body --event <json>` before opening.
