# Ruling needed: whether your unasked notes, written into a decision record, count as questions or as instructions you gave unasked

Milestone: M8

Some decision records hold, beside your answers, notes you gave without being asked, written in word for word. The counting rules today count each such note as one more question you answered. A separate rule, which an earlier card asks you about, counts instructions you give unasked under a code of their own. So if you ruled that kind out, these notes would still be counted. In the sample, no piece's result changes either way, because the one piece concerned also holds real answers in its window. Nothing is frozen, so nothing here is irreversible.

WHY: the count should put each of your touches under the code that describes it, so that your ruling on unasked instructions applies to all of them; the plan does not change until you choose (specs/S-002.md, open question 16).
OPTIONS:
  A. Keep them counted as questions, as the rules read today, and list them.
     Gain: no new reading rule.
     Cost: your ruling on unasked instructions would not reach them.
  B. Count a note under the unasked-instruction code when all of its lines sit under a line naming your note or notes, and none under a line naming an answer or a ruling; list each one so coded for the Critic's check.
     Gain: one code for one kind of touch, kept in view in past records.
     Cost: one more reading rule, and a check of each one coded.
  C. Leave such notes to the touch log alone.
     Gain: simplest.
     Cost: it drops them from past records, where the touch log holds nothing.
RECOMMENDATION: B, with fair confidence (the Definer's and the Chief of Staff's judgement): these notes are what the unasked-instruction code describes, and B keeps them in view in past records, which C would lose. What would change it: if notes cannot be told from answers in enough records, then A.
WHO HAS CHECKED IT: the Critic's step 5 on memo 3 raised it (reviews/Q-018-recode-2/_critic-verbatim.md, finding 8(b) and open questions); the Definer wrote the options (docs/briefs/305-definer.md).
