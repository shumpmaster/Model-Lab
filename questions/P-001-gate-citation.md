# Ruling needed: how should the Build gate's case show you the plan's criteria, while the checks cannot open the plan?

Milestone: Design-6

The case for moving the prompt engine into Build is on hold. The independent check of the case found that it does not show you the criteria you would be approving, or the plan's budget options and open questions, and carries too few risks. The risks can be fixed as things stand. The criteria cannot: every line of a case must point to a record that the case's own check can open, and that check cannot open the plan. It learns which plan belongs to the project only from the pipeline's status record, which this conversation-run project does not have; your earlier ruling sent that gap to a change in the operating model, which has not been written yet. This asks how the case should carry the criteria meanwhile. Nothing here is irreversible.

WHY: the gate case is what you rule the Build gate on, and the criteria by scenario are the thing the model says you approve there; until this is settled, the case cannot be reworked, and the gate waits (Personal-Org-Operating-Model OPERATING_MODEL.md §2 and §4 "Phase gates"; reviews/P-001/_build-gate-1-critic.md).
OPTIONS:
  A. the case points straight at the plan, and the check stays red on those lines — the case quotes the criteria, power figures and options and points at the plan for each. The case's check refuses every such line ("not one the Critic's gate pack holds"), so the governance check on the gate's pull request stays red after your verdict on the reading lists, and runs red again on the default branch when it is merged, since that run checks the merged changes too; every later change to the case is red the same way. Gain: the fastest; the case cites the plan itself. Cost: you would merge past a red check, and a known red teaches everyone to read past red (lessons 29, 42, 48). Whether GitHub lets you merge past it depends on this repository's settings, which I cannot read. Reversible: yes.
  B. the criteria go into the gate's "proposal" file beside the case, and the case points at that — the proposal is the one-page view the model writes for a user representative; here you are the user, so no representative reads it, and it is used only as a record the check can open. Its "How you would use it" section holds the plan's eleven criteria, each word for word, and the check confirms every one against its line in the plan; the case then points at those lines. The plan's run and week totals are pointed at in the plan's review, which the check can open; its power figures are in that review only in part, so they stay on the gate card, as now, unless the proposal also quotes the plan's own lines on size, which the check would accept but which is not what the section is for. Gain: every check stays green, and the criteria you see are proven to be the plan's own words. Cost: the criteria appear twice; the proposal is used for something it was not designed for, which the case says; the pipeline's script ignores the file, since it acts only on status records, and runs a user representative only for a project with a target-user profile, and this one has neither. Reversible: yes.
  C. the gate waits for the operating-model change — first the change your earlier ruling chose, so the checks see your recorded rulings, is specified, built, reviewed and merged in the operating model's repository, then copied here; it would also let the checks open this project's plan. Gain: the cause is fixed for every conversation-run project, with no copy and no red. Cost: nothing has been specified yet, and the one plan now in that repository's queue has stopped twice in review; how long it takes is not known, and the gate, the plan's freeze and the test wait until then. Reversible: yes.
  The change in C stays owed under every option: your earlier ruling stands, and A or B only bridge this one gate.
RECOMMENDATION: B, with medium confidence (the Chief of Staff's judgement): it keeps every check honest and green, the check itself proves the criteria are the plan's words, and the gate is not held for a change of unknown length. What would change it: if you would rather not see the proposal form used for something it was not made for (then A, if a red check is acceptable to you, or C, if the gate can wait).
WHO HAS CHECKED IT: the Critic, on a different AI model from the writer (its record will be named here once it has read this card).

DEFAULT: B   TIMEOUT: 72 hours
