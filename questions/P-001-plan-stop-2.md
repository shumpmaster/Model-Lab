# Ruling needed: how the fair test's plan goes on after the focused review failed

Milestone: M2, Design-5, Design-6

The focused fix you chose cleared five of the seven points it set out to fix, but the review that checked it failed the plan on two new ones, both about secrecy. The helper that writes the secret marking sheets is meant never to see the plan, and the work being judged is meant never to see the sheets. In practice neither is enforced here, because every helper started from a session shares that session's machine and can open anything on it, and the plan does not name who may handle the sheets when each judge is given one. The independent trace found that better wording can only add a check that catches a look afterwards; keeping the secrets out of reach needs the secret steps run in separate sessions, which ties this choice to where the sheets are kept, asked beside it (Triage, round 5). The rules stop the plan until you choose. Dropping the test cannot be undone within this project.

WHY: the plan cannot be frozen, and the Build gate cannot come to you, until it passes; a failure in the focused review goes back to the owner the same way (Personal-Org-Operating-Model AGENTS.md, "Plan stop rule"; reviews/S-001/plan.md, "Round 5"; triage/P-001-S-001-round-5.md).
OPTIONS:
  A. Re-specify how the test is run — Gain: the secrecy is real: the sheet writer and the judges run in their own sessions, which never hold the plan or the work. What happens: the plan's writer rewrites the steps for writing the sheets, running the work and judging around separate sessions, keeping the measures, size and options; as a new draft, it is reviewed from round one. Fits the storage choices that keep the sheets apart (the new repository, or you keeping them). Cost: not estimated; more review rounds, and separate sessions to set up for each judging. Rules out: the storage choice that relies on instruction only.
  B. Re-scope to secrecy that is checked, not enforced — Gain: the plan's way of running stays close to what passed review. What happens: the plan says plainly that the sheets and the plan are kept apart by instruction, adds a check of each secret helper's record of what it opened (a look voids that kind's sheet), and names the coordinating role as the one that hands each judge its sheet; a narrowed plan is a new draft, reviewed from round one. Cost: not estimated; a weaker test, and no record yet shows that each helper's record of what it opened is kept for such a check. Rules out: a test whose secrecy is enforced.
  C. Drop — Gain: no further work or runs on the test. What happens: the fair test is not run. Cost: no answer on whether any change helps. Rules out: any answer to the question this project set out to test, unless a new plan is made later.
  D. Another focused confirmation review — Gain: the fewest rounds. What happens: the plan's writer fixes the two points in the way your storage choice allows, and one review checks only those. Cost: not estimated. Whether the rule allows a second focused review is unclear: it offers "one focused confirmation review" and sends a failure in it "back to the owner the same way"; you rule how it reads (Triage, round 5). Rules out: nothing, if the rule allows it.
RECOMMENDATION: A, with the new private repository for the sheets — the test's worth rests on its secrets, and A is the only route that enforces them; it keeps what passed review and redoes only how the test is run. What would change it: if you prefer not to set up separate sessions, B; if you rule the rule allows it, D with A's change is the shorter path (triage/P-001-S-001-round-5.md, "Which the evidence supports").
