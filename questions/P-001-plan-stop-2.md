# Ruling needed: how the fair test's plan goes on after the focused review failed

Milestone: M2, Design-5, Design-6

The focused fix you chose fully cleared five of its seven points, one more only on paper and one only in part, and the review that checked it failed the plan on two new points, both about secrecy. The helper that writes the secret marking sheets is meant never to see the plan, and the work being judged is meant never to see the sheets. Neither is enforced as the plan stands: every helper started from a session shares that session's machine and can open anything on it, and the plan names no one allowed to hand each judge its sheet. Better wording alone could only catch a look afterwards. You have chosen to keep the sheets in a new private repository given only to judging sessions, so the remaining choice is how the plan is rewritten to match. Dropping the test, one option, cannot be undone within this project.

WHY: the plan cannot be frozen, and the Build gate cannot come to you, until it passes; a failure in the focused review goes back to the owner the same way (Personal-Org-Operating-Model AGENTS.md, "Plan stop rule"; reviews/S-001/plan.md, "Round 5"; triage/P-001-S-001-round-5.md).
OPTIONS:
  A. Re-specify how the test is run — Gain: the plan matches your storage choice: the sheet writer runs in a session that never holds the plan, and the judges in sessions that never share a machine with the helpers doing the work. What happens: the plan's writer rewrites the steps for writing the sheets, running the work and judging around separate sessions, keeping the measures, size and options that passed review, and settling how each sheet reaches the repository (for example, you place it); as a new draft it is reviewed from round one. Whether separate sessions keep the sheets out of reach is not yet tested; the first judging would confirm it. Cost: not estimated; more review rounds than B, and separate sessions to set up for the sheet writer and for each judging. Rules out: nothing.
  B. Another focused confirmation review — Gain: the same rewrite as A, checked by one review of the rewritten steps only, so fewer rounds. What happens: as A, but the review looks only at the rewritten steps and what they touch, not the whole plan. Cost: not estimated; a narrower check of a change the trace calls a redesign of those steps, not a patch. Whether the rule allows a second focused review is unclear: it offers "one focused confirmation review" and sends a failure in it "back to the owner the same way"; choosing this rules that it does. Rules out: nothing.
  C. Drop — Gain: no further work or runs on the test. What happens: the fair test is not run, and the storage choice falls away. Cost: no answer on whether any change helps. Rules out: any answer to the question this project set out to test, unless a new plan is made later.
  Re-scoping to secrecy that is only checked afterwards is not offered: it fits only the portfolio folder, which you did not choose.
RECOMMENDATION: A — the trace found that, with the sheets kept apart, the fix is a redesign of how the test is run and should be reviewed as one; A keeps what passed and gives the redesign a full review (triage/P-001-S-001-round-5.md, "Which the evidence supports").
