# Ruling needed: the fair test's leak check is stricter than its rules in some places and misses some routes; keep it as it is, or change it before the first runs

Milestone: M4, Build-3

The harness that runs the fair test passed its review, but the Reviewer left you some trade-offs in its leak check. The leak check is the part that decides whether a helper looked outside the copy it was given. In some places it is stricter than the written rules: a commit message or a line of printed text that only mentions a path reads as a leak, and each such hit throws away a pair along with the runs already spent on it. In a few places it lets things through: a script the helper writes with its file tool and then runs is not looked inside, and neither is a path its code builds. The helpers doing the tested work are told to stay in their copies, and their session holds the real work repositories; this check is what shows whether they stayed. The harness has used the three build rounds the stop rule gives, and you have said any change to it now needs your ruling. Nothing has been changed, and no test run has been spent.

WHY: the check decides which pairs count, so it bears on the fair test's result, and changing the harness now goes past the three build rounds. The AC2 prefix-only check is not asked here: you set it aside for a later change, with the three earlier points.
OPTIONS:
  A. Keep it as it is — the harness is unchanged, and every stricter reading and gap is listed in each kind's result as a known limit of the check. Gain: no fourth round, nothing new to go wrong, and the first kind's list of left-out pairs, each with its line, gives the count of what each reading costs. Cost: each stricter hit loses its pair (2 to 4 runs spent, or the held-back check's sheet), at a rate not measured for new built work: in 911 real calls of earlier work the Reviewer found commit messages and printed text nowhere, and patterns in code on 4 lines of one transcript left out anyway; the gaps stay open. Rules out: nothing; a change can follow the first kind.
  B. Narrow the plainest readings — a new Builder stops reading path-like text in commit messages and printed text as leaks (`echo /` and `/.` included), and adds `//` as the root; a Reviewer runs every case; the other gaps are listed as limits. Gain: fewer pairs lost to forms the Reviewer judges likely in built work. Cost: a round past the three the stop rule counts, which no rule covers; a fresh Builder and Reviewer (their first rounds reported about 355,000 and 246,000 tokens); the Builder's own tests change; a fix to these readings has made a new mistake here before. Rules out: nothing.
  C. B, and also look inside scripts written by the file tools — as for scripts written through the shell. Gain: closes the route the Reviewer found more common than the shell for writing a script. Cost: as B; and code in such files that holds a pattern or a system path reads as a leak, as two test files written in the earlier work would. Rules out: nothing.
  Under every option the record of a brief keeps the form the harness reads, "recorded: at hand-out, <date>", as all 40 such records already do; one written otherwise would lose its piece before any run. If you would rather the harness read the date instead, it joins B's round.
RECOMMENDATION: A, with medium confidence (the Chief of Staff's judgement): the cost of the stricter readings is not measured for new built work, and the first kind gives that count without a round no rule gives. What would change it: wanting fewer pairs lost from the start (then B), or wanting the file-tool route closed before any run (then C).
WHO HAS CHECKED IT: the Reviewer found each reading and gap; the Chief of Staff ran the harness on every case on a copy; the Critic checks this card.

DEFAULT: none, since each option bears on the frozen test's harness after its last round, which only you rule   TIMEOUT: none
