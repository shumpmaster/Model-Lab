# Research question — Q-017

*Drafted by the Chief of Staff and checked by the Critic for gaps and neutral phrasing (D-032, D-055).*

## The question

A small organisation does its work through AI agents, each started for one task, and one person, the owner, who reviews, decides and merges. Its work is kept in three git repositories (on GitHub as shumpmaster/Service-Desk, shumpmaster/Model-Lab and shumpmaster/Personal-Org-Operating-Model). Their records as of 2026-11-09 are given to you as an extract in /home/user/Model-Lab/research/Q-017-extract/: for each repository, a file of commits and a file of merged pull requests. Its README.md says how each was made and what each field means; extract.py is the script that made them. Count, from the extract alone, who made and merged the changes, how often the owner was asked to decide, and how often merged changes were later reverted or changed again. Give every count at both ends (for example, with and without a commit by the owner).

1. **Units.** Count merged pull requests, per repository and per month of merged_at (UTC), from <repo>.prs.jsonl. Class each by kind from the paths it changes, with a stated rule:
   - built work: code, tests, tools and their configuration;
   - a plan or spec;
   - research: research questions, memos and their checks;
   - records only: logs, ledgers, digests, review and session records, briefs, and other files that record work rather than do it;
   - an owner question or answer: paths labelled <questions:…> or <decisions:…>;
   - other.

   A pull request that fits two kinds is counted under each and flagged. A commit belongs to a pull request when it is listed in that pull request's commits; count separately the commits on the default branch that belong to no merged pull request (direct pushes, or work whose pull request is not in the extract). Give the number of changed lines as a second view beside each count.

2. **Who made and merged each change.**
   - Identities: the extract classes each commit's author as agent, owner or other, and gives author and committer names. List the names in each class, and say how you treat the "other" names.
   - For each merged pull request: its commits by author class, its co-author classes, and the author of its merge commit, which for a merge is the account that merged it. For a squash the merging account is not recorded, and the commit's author is the pull request's author: count squashes separately and say what they can and cannot show. Give the shares at both ends (with and without a commit by the owner's identity, and with each kind of merging account), and the same counts at commit level.
   - Limit: an identity is not proof of who did the work. An agent session may commit under the owner's git settings, and work from before the agents.invalid convention began carries another identity. Say from what date the convention appears in each repository.

3. **Questions put to the owner.** The number of files first added with a <questions:…> label, and the number first added with a <decisions:…> label, per month and per merged pull request. A question and its answer have different labels, so say whether and how they can be matched (for example by a pull request that adds the answer and removes the question); where they cannot, say so. Limit: a question file does not prove the owner was asked, nor an answer file who answered, and decisions given in conversation leave no file.

4. **Merged changes later reverted or changed again.** For each merged pull request, whether a later commit is marked revert or names it (mentions_prs), or a later merged pull request changes the same files, within 14, 30 and 60 days of its merged_at; a later commit or pull request falls in a window by its commit_date or merged_at. Same files is a coarse test, since the extract has no line-level history; say so, and report the reverts and the naming separately from file overlap. Leave out files that are edited in turn by design (logs, ledgers, digests, generated files, and the session and dispatch records), and say which kinds of file you left out and how many. Report separately pull requests merged less than 60 days before 2026-11-09, whose windows are not complete. This counts later changes; it does not judge whether the earlier change was at fault.

5. **What the records cannot show.** For example: decisions and approvals given in conversation; the owner's time; work dropped before any record; fixes that do not name what they fix; pull request titles, reviews and comments, and pull requests closed without merging, none of which is in the extract; how the extract's coding could be wrong (say where you doubt it); and the limits named above.

Report every figure on equal terms; whether any figure is large or small is not for this memo to judge.

**What you may read.** The files in /home/user/Model-Lab/research/Q-017-extract/ and this question, and nothing else: no other file in the three repositories, no git or GitHub, and no web. File paths in the extract, labelled or not, may be used only to count, class and match; do not report any path, label or file name.

Out of scope: outside literature, earlier counts of these records, and any recommendation of what to change.

## The decision it serves

A described baseline of the organisation's own records: who makes and merges its changes, how often its owner is asked to decide, how its checked work fares, and how often merged changes are changed again.

## What each answer would change

Each count is marked as one the extract supports, supports only in part, or cannot support, with what it would take to measure it; what the extract cannot show is stated as a limit on any use of these figures.
