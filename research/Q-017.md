# Research question — Q-017

*Drafted by the Chief of Staff; checked by the Critic for gaps and neutral phrasing (D-032, D-055). Never state or hint at the hoped-for answer.*

## The question

In the records of work done under the operating model, how much of the work did agents carry from start to merge, how often did the person who supervises them step in, and how often did merged work need correcting later, as far as the records allow?

1. **Units.** Count by merged pull request, per repository and per month, and say how a pull request is classed by kind (built work, plan, research, records only, owner question or answer, or other) from its title, files and labels. Define every count before making it.
2. **Who did the work.** For each merged pull request, the commits by an agent identity (an address ending in agents.invalid), by the supervisor's own identity, and by any other identity. Give the share of merged pull requests with no commit by the supervisor's identity, and list the others.
3. **How often the supervisor was asked.** The number of question files filed (added under questions/) and answered (added under decisions/questions/), per month and per merged pull request, from file names and commit dates only.
4. **Rounds of checking.** From reviews/ and research/*-source-check.md, the rounds each checked piece took before passing, and how many reached the stop rule (three failed rounds).
5. **Whether merged work held up.** Merged work later reverted, or corrected by a later pull request that names it or edits the same lines within 30 days, as far as commit history and the lessons logs (docs/LESSONS.md and its equivalents) show. Say how each case was found, and what the method cannot see.
6. **What the records cannot show.** For example, work done outside the records, the supervisor's time, or a fix made without naming what it fixed.

Report every figure on equal terms; whether any figure is large or small is not for this memo to judge.

Records to read: the git history, pull request merge commits and file lists of shumpmaster/Service-Desk, shumpmaster/Model-Lab and shumpmaster/Personal-Org-Operating-Model, and their reviews/, research/*-source-check.md, docs/briefs/, sessions/ and lessons logs. Under questions/ and decisions/, read file names and commit dates only, never the files' contents. Do not read docs/projects/, docs/PROJECT.md or any ideas/ folder. Earlier counts are in Model-Lab research/Q-006-memo.md and Q-008-memo.md; re-derive every figure you use, and where yours differs, say which record decides it.

Out of scope: outside literature, and any recommendation of what to change.

## The decision it serves

The starting figures against which a value target for the screening project is set: the share of work agents carry, how often the supervisor steps in, and whether delivered work holds up.

## What each answer would change

Each count becomes a candidate starting figure for a value target; a count the records cannot support is set aside or measured from new work instead; what the records cannot show is stated as a limit on any target built on them.
