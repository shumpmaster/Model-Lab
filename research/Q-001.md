# Research question — Q-001

## The question

Groundwork map: the written instructions that pass work between roles in a multi-step pipeline of AI agents under one human owner.

In this pipeline, each agent session starts fresh and works only from what it is handed: a standing role definition (its duties, what it may read and must not see, its handoff) and a task brief written for each dispatch (what to produce, to what standard, from which inputs). Independent checkers then review the work, and failed work goes back for another round with the checker's findings. The pipeline is described in shumpmaster/Personal-Org-Operating-Model (OPERATING_MODEL.md, and the role definitions in template-v3/.claude/agents/, template-v3/governance/BRIEFS.toml and PACKS.toml); one project run under it is shumpmaster/Service-Desk.

Map the ground an expert would cover before deciding whether and how these instructions should be changed, observed or measured:
- what determines whether an agent session produces good work, and how much of that the instructions explain compared with other factors (the model, the inputs, how the task is split, the checks);
- whether, and how, instruction quality can be observed or measured, and against what baseline, including leaving things as they are; and how to tell a real improvement from run-to-run variation when runs are few;
- how instruction versions are recorded, tied to the work produced under them, and rolled back;
- how the answers differ by kind of task (research, definition, build, review, triage, a question put to the owner), and for the findings a checker hands back with failed work;
- how the standing role definition and the per-task brief interact, including when they conflict;
- whether instructions carry over when the model behind a role changes;
- what writing, running and measuring instructions costs in agent runs and money, and how that limits what can be tried;
- how much of the owner's time each approach needs, and which decisions can only be the owner's;
- how this interacts with the pipeline's existing reviews and checks;
- the risks of changing instructions in response to individual failures, including growth, conflict between rules, and fitting to the checks rather than the goal;
- what other fields have learned about written instructions handed between people or teams, including where written procedure was found to help little or to harm.

## The decision it serves

The shape of the Discovery for this project: which questions go to the owner, which go to research, and which need an experiment, before its value target, scope and plan are set.

## What each answer would change

Each area found to be unknown becomes a research request or a registered experiment; each found to be the owner's call goes on the owner's shortlist; each design trap found shapes the scope.
