**The question.** Will the check that judges the fair test give the same verdict on the same work when asked again? And does a judge on the same AI model as the work judge it more kindly than the test's judge on a different model?

## Who does what
The Builder runs this check exactly as registered and starts every helper session (the experiment playbook). The Reviewer, which did not run it, analyses the results against the thresholds; the orchestrator records its verdict verbatim. E-002 runs after E-001, because it judges E-001's replays.

## Hypothesis
The test judge gives the same verdict on the same piece when it judges it twice, and agrees with a judge on the work's own model, closely enough that the fair test's verdicts reflect the work rather than the judge. Either outcome is a result: if it holds, M2 uses the test judge, with the limits below stated; if not, or if the check cannot test it, M2 uses the brief's fallback.

## Method
**The models.** All helpers come from one provider (the environment check). The work in Set B is done on Opus 5.5 (E-001's replays). The **test judge** is Fable 5.1, the only available model outside the work's 5.5 line, so the nearest this plan offers to "a different model family" (docs/PROJECT.md section 8); whether it is a different family is not established. The **same-model judge** is Opus 5.5. Two caveats:
- A disagreement between Fable 5.1 and Opus 5.5 may come from a difference in what each can do as a checker, not from bias; this check cannot tell the two apart.
- The premise "the judge is on a different model from the work" holds only for Set B. Set C's and any substitute's original workers ran on models mostly not recorded.

**The judge-brief template.** Every judgement uses it; the Builder fills each `<…>` once per piece from files at the piece's commit and the piece itself, and every judgement of that piece gets the same filled text, byte for byte, whatever the model, so that a difference between judgements cannot come from the brief. E-001's check runs use it too.
```
You are the <checker role id> (your role file: <checker role file path at the piece's commit>),
doing the <plan review | build review | source check> of <piece id>.

Read your role file and the files its context pack names, as they are in <copy path>. The work
to judge: <the submission's paths, or the commit range <base>..<head> in the copy>. Judge it
against: <the spec, criteria or request it answers, path at that commit>.

Work only in <copy path>. Do not read, search or run commands on any path outside it, do not
use the web, and do not run git commands that reach any other repository. You are one of
several independent judgements and see no other verdict.

Return, first line: `Verdict: PASS` or `Verdict: FAIL`. Then each blocking finding as one
numbered line citing file:line.
```
The copy is made as in E-001 step 2.1: a fresh repository holding only the commit judged (the piece's submission, or the replay's output on its start commit) and its ancestors.

**The pieces.**
- **Set B (up to 8):** E-001's replays that passed F4–F6 and got a verdict (F7). Each is judged three times: by the test judge twice (the first is E-001's own check run) and by the same-model judge once.
- **Set C (2):** past pieces that passed their check first time, so the set is not all failed work. Each piece's round-1 submission is its only one, recovered from git at the commit its round-1 check names (here that commit is right: it is the work judged). Each is judged twice by the test judge. They are the first two of E-001's first-time-pass pieces, in its list order, whose submission and check pack can be recovered, one plan and one built work where possible.
- **Substitutes:** a Set B place left empty (E-001 ran fewer than 8 replays, or a replay failed F4–F7) is filled from the returned pieces of Q-008's §3 samples not audited in E-001, in list order, alternating SD and POOM, plans first: SD job-prs-recorded, POOM S-023, SD desk-v2 stage 1a, POOM S-015 proof-diag, SD records, POOM S-024, SD desk-v2 stage 3, POOM S-032, and so on. Each is the piece's round-1 submission, which for several is not the round Q-008 sampled (S-023 was sampled at round 11, job-prs-recorded at round 2); the round-1 submission is used because it is the work first put to the check. A substitute is judged twice by the test judge; its worker model is unknown, so it adds to consistency only. A piece whose submission cannot be recovered is skipped and listed.

**Research.** A source check must open every cited source, and this check reads no web, so research that rests on web pages cannot be judged by the test judge at all here. A research piece enters only as one of E-001's web-free replays.

## Measure
- **Consistency (deciding):** over the consistency set (Set B, Set C and substitutes, up to 10 pieces), on how many the test judge's two verdicts differ. Whether the blocking findings overlap is reported beside it.
- **Pieces with a pass (gate on the result):** pieces in the consistency set where at least one test-judge verdict is PASS; and Set B pieces where either judge returned PASS.
- **Judges' agreement (deciding):** on how many Set B pieces the test judge's first verdict and the same-model judge's verdict differ, and in which direction.
- **Agreement with the record (reported, not deciding):** the test judge's verdict beside the recorded round-1 verdict, for Set C and substitutes; the original judge's model and brief are not recorded.
- **Cost:** tokens, tool uses and time per run, as each helper reports at return.

## Sample
Up to 10 pieces for consistency; up to 8 (Set B) for judges' agreement.

**Runs.** One run is one helper session started for this check, whatever it does; a session that errors still counts. E-001's check runs count in E-001. E-002 starts 2 sessions per Set B piece (the test judge's second verdict, the same-model verdict), 2 per substitute and 2 per Set C piece: at most 8 × 2 + 2 × 2 = 20. **Hard cap:** at most 20 helper sessions started, counted as started, whatever their outcome; with E-001's cap of 20, together at most 40 of the 100 runs allowed through Design (docs/PROJECT.md section 8). No judgement is repeated for a better answer (D-047).

**What this size can show.**
- *Consistency:* only gross inconsistency. Over 10 pieces, a judge that flips 1 verdict in 4 would still clear the bar below about 24 times in 100, and one that flips half its verdicts about 1 time in 100 (binomial, at most 1 flip). A pass means "no gross inconsistency found", not "consistent".
- *Self-preference:* only a large one. A same-model judge that passes 2 of 8 pieces the test judge fails, and none the other way (25 points, more than V1's 20-point gain), still clears the bar. A pass means "no large self-preference found".

## Exclusions
- Kinds other than plans, research and built work, as in E-001.
- Research resting on web pages (above).
- Pieces with no recorded verdict (Q-008 lists them), and pieces whose submission or check pack cannot be recovered, each listed with its reason.

## Deciding threshold
Set now:
- **Not tested** if fewer than 6 pieces get both test-judge verdicts, or fewer than 3 pieces in the consistency set have a test-judge PASS, or fewer than 4 Set B pieces get both judges' verdicts, or fewer than 2 Set B pieces have a PASS from either judge. Agreement among verdicts that are nearly all FAIL shows nothing. "Not tested" triggers the fallback.
- **Pass (consistent, judges agree):** tested, **and** the test judge differs from itself on at most 1 piece, **and** the two judges differ on at most 2 Set B pieces. M2 uses the test judge (Fable 5.1) for both arms, and its record states the limits in this file.
- **Fallback (U3, docs/PROJECT.md section 7)** if the test judge differs from itself on 2 or more pieces, **or** the two judges differ on 3 or more Set B pieces in either direction: a held-back set of checks the work never sees and the owner's own sample decide the test's verdicts, and M2's record states the limit.
- The direction of the judges' differences is reported with every result. Below 3 differences it is a reading only: it changes nothing M2 does.

## Where the one-provider limit weakens this check
Every judge comes from the same provider as the work. Models from one provider may share training methods, data and habits, so a bias they share, such as preferring work written the way that provider's models write, would make them agree and would not show here. A pass shows only that two models from one provider repeat themselves and agree; it cannot show the judges are unbiased in the sense R3 asks. Whether Fable 5.1 is a different family is not established, so the brief's "different family" may not be met at all. Only a judge outside the provider could test the shared bias, and that needs the owner to override the spend ceiling in their own words (decisions/questions/P-001-spend-ceiling.md). Within the plan, the owner's own sample in the fallback is the only judgement from outside the provider.

## Holdout use
None. The held-back set of checks the fallback would use is M2's and is not seen here. The pieces used here are listed in the result, so M2 can keep them out of its held-back set and its test pool.
